# RK3566 监控台 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建显示 K230 RTSP 视频和跌倒统计的 RK3566 Qt TCP 服务端监控台。

**Architecture:** `Widget` 管理 `QTcpServer`、当前客户端 socket 和收包缓冲区；独立的纯 C++ `StatusProtocol` 解析器将文本帧转成已校验的数据。Qt Multimedia 使用 `QMediaPlayer/QVideoWidget` 在同一窗口播放 RTSP，Widgets 布局负责状态卡、告警和日志。

**Tech Stack:** C++17、Qt 5.15 Widgets/Network/Multimedia、QTest、GStreamer 多媒体后端。

**Spec:** `docs/superpowers/specs/2026-10-26-rk3566-monitor-design.md`

## Global Constraints

- TCP 监听地址为 `192.168.10.3:9000`。
- RTSP 地址为 `rtsp://192.168.50.2:8554/BackChannelTest`。
- 状态帧按换行分隔，TCP 半包/粘包均须正确处理。
- 有效帧回 `ACK seq=<seq>\n`，无效帧回 `ERR reason=invalid_status\n`。
- 所有网络 API 均须有中文 Doxygen 注释。
- 编译前安装 `qtmultimedia5-dev`，运行依赖可用 Qt Multimedia/GStreamer 解码后端。

## Review Focus

- 半条 `STATUS` 帧到达时不得提前更新界面或回复 ACK（Task 2 测试）。
- 一次读取含多个完整帧时必须逐帧解析与应答（Task 3 测试）。
- `total != standing + fallen`、错误 state 或缺失字段必须返回 ERR（Task 2 测试）。
- 旧客户端未断开时有新连接，旧连接应关闭且新连接成为当前源（Task 3 手工验证）。
- RTSP 不可达或后端报错时，TCP 监听与人数更新必须继续工作（Task 4 手工验证）。
