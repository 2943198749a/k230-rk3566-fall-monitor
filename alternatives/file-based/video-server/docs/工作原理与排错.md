# 工作原理、调用链和排错

## 一、设备与线程

本机已验证的设备号：`/dev/video2` 给 YOLO 推理，`/dev/video3` 给 1080p RTSP；原始官方 720p 另用 `/dev/video1`。这些数字与实际设备树和内核枚举有关，换镜像后必须用 `v4l2-ctl --list-devices` 核对。V4L2 的非 AI 2D 设备另由 `osd.cpp` 根据设备名查找，硬件编码器为 V4L2 M2M。

```text
OV5647 + ISP
  ├─ video2 → ai_proc → nncase KPU → 后处理 → 临时文件 /tmp/yolo_fall_boxes
  └─ video3 → 采集线程 → 原始帧队列 → 叠框 → H.264 编码 → Live555 RTSP → VLC
```

YOLO 和 RTSP 是独立进程。1080p 流不是从 `/dev/video2` 的 AI 输入直接编码的，而是另一 ISP 通道；即使两个通道来自同一个摄像头，也可能存在时间差。叠框是读取最近结果而不是严格逐帧配对。

## 二、从程序入口读代码

1. `source/ai_demo/falldown_publish/main.cc` 的 `main()` 在输入模式 `None` 时启动 `ai_proc`，等待标准输入 `q` 后退出。`ai_proc` 用 V4L2 捕获 BG3P 数据、封装张量、执行预处理、推理及后处理。
2. `falldown_detect.cc`：`pre_process()` 使用 AI2D 做缩放填充，`inference()` 执行 KPU 模型，`post_process()` 完成解码与 NMS。结果标签由头文件的 `labels` 定义为 `Fall`、`NoFall`。
3. 推理侧先写 `/tmp/yolo_fall_boxes.tmp`，再用 `rename()` 原子替换 `/tmp/yolo_fall_boxes`。每行依次是 `label score x1 y1 x2 y2`；无目标时文件为空。坐标属于传感器尺寸 1920×1080。
4. `source/rtsp/main.cpp` 设置 `/dev/video3` 和 RTSP `8556/yolo`。`camera_rtsp_demo.cpp` 创建 RTSP 会话，`media.cpp` 采集、叠图、编码并调用 `OnVEncData()`；后者通过 `librtsp_server` 发送 H.264。
5. `OnUpdateOsdRegions()` 用文件修改时间判断结果是否超过 3 秒，过期不画框。它用 1920×1080 画布和 4 个 960×540 OSD 区域绘制，每个缓冲 4096 字节对齐。字节通道按当前 FFmpeg 非 AI 2D OSD 的 ARGB 约定组织；不要将 OpenCV 默认 BGRA 通道顺序当作 ARGB。
6. `osd.cpp` 调用 FFmpeg `nonai2d_osd`；销毁 filter graph 前清空外部区域指针，避免该 SDK 滤镜清理外部指针时 `free(): invalid pointer`。此措施针对当前 SDK 版本，升级时须重新核实。
7. `media.cpp` 原始采集队列上限 6，满时丢最旧的未编码帧。尝试过改为 1，但用户反馈画面变卡或花屏，最终使用 6。不要直接删除已编码 H.264 的任意帧，以免破坏帧间依赖。

## 三、前台分别启动（便于学习）

以下命令在 K230 Linux 上，且仅在旧程序均已退出、设备与端口可用时执行。

终端一：

```sh
cd /root/k230-yolo-repro
./falldown_publish.elf yolov5n-falldown.kmodel 0.5 0.45 None 0
```

保持终端打开；模型每次有推理会更新 `/tmp/yolo_fall_boxes`，`q` 回车退出。标准输入关闭时该程序也会退出。

终端二：

```sh
cd /root/k230-yolo-repro
./camera_rtsp_yolo_1080 -t h264 -w 1920 -h 1080 -b 5000 -r 4
```

这里的画布和坐标按 1920×1080 写死，必须和 `-w 1920 -h 1080 -r 4` 一致；修改分辨率或 OSD 数量前，需要同步改源码并重新验证。RTSP 自己不会启动 YOLO。

## 四、常见问题

- **没有 `/proc/vsi/isp_subdev0`**：确认 Linux ISP 驱动及 `/etc/init.d/S31canaan_isp` 正常，确认镜像类型。不要在流运行中反复重启 ISP。
- **ISP 识别为 GC2093 / `Remote I/O error`**：检查实际模块是否 OV5647；用匹配镜像的 ISP 配置选择 OV5647。重启前先核对原厂自动/手动 JSON 与 XML。排线检查前先断电。
- **`display_init` 报错**：官方原始摄像头 demo 要显示器；本包的 YOLO 改为无屏采集。RTSP 视频本身不需要本地屏幕。
- **端口通但无画面**：`ps` 查看进程、`netstat -lnt` 查看 8556，检查摄像头设备、资源占用、VLC 的 TCP/UDP 和防火墙；端口监听不等于视频已送出。
- **无框**：站到镜头前，检查推理日志、`cat /tmp/yolo_fall_boxes` 的更新和模型路径。空文件可以是当前没检测到目标；超过 3 秒的结果不会绘制。
- **方向不对**：调整摄像头本体使原始输入正确；VLC 后处理旋转不会改变模型输入。
- **无法交叉编译 / features.h 缺失**：`SDK_ROOT/output/k230_canmv_v3_defconfig/staging` 没准备好。仅有一个 demo 目录及交叉 GCC 不足以提供所有 SDK 头文件和库。
- **Ubuntu 26.04 的 host-m4 编译报错**：本机遇到过 GCC 15 与主机工具不兼容。优先使用与 SDK 匹配的 Ubuntu 22.04 容器及干净构建目录，避免跨不同 GLIBC 复用主机产物。
- **报 `GLIBC_2.38 not found`**：不要在 Ubuntu 22.04 容器内复用 Ubuntu 26.04 产生的 host 构建工具；隔离旧输出目录后重建。重建会耗时且占空间。
- **`/tmp` 日志丢失**：tmpfs 重启会清空；排查重启或断电问题前，应先保存日志到持久位置。
