# 协议与接口说明

## 1. 大核程序命令行

```text
falldown_rtsp_status_safe_v3.elf <kmodel> <obj_thresh> <nms_thresh> <debug_mode>
```

- `kmodel`：KModel 路径。
- `obj_thresh`：候选检测框置信度阈值，已验证命令使用 `0.5`。
- `nms_thresh`：NMS IoU 阈值，已验证命令使用 `0.45`。
- `debug_mode`：0 不输出阶段计时；1 输出简要耗时；2 输出更详细诊断。

阈值不是越低越好。降低目标阈值会增加召回，也会增加误检和 NMS 负担；应使用真实场景验证集调整。

## 2. 视频 DataFIFO 协议

写入方：K230 RT-Smart 大核。读取方：K230 Linux 小核 `rtspServer`。

```c
struct VideoRecordPrefix {
    uint64_t pts;
    uint32_t encoded_length;
    // uint8_t encoded_h264[encoded_length];
};
```

当前实现依赖 RV64 上 `unsigned long` 为 64 位，小核按 8 + 4 字节偏移解析。码流是 H.264 Annex-B 数据，包括 VENC header 和 frame packs。单槽 `BLOCK_LEN=1024000`，槽数 10。

兼容规则：只要改变字段顺序、宽度、对齐、槽大小或编码类型，就必须同时修改两端并重新构建，不能只替换其中一个二进制。

## 3. 状态 DataFIFO 协议

定义在 `k230/common/status_protocol.h`：

```c++
struct alignas(64) DetectionStatus {
    uint32_t magic;      // 0x46414C4C, ASCII "FALL"
    uint32_t version;    // 当前为 1
    uint32_t sequence;   // 推理序列号
    uint32_t total;      // 识别到的总人数
    uint32_t standing;   // NoFall 类别数量
    uint32_t fallen;     // Fall 类别数量
};
```

结构体实际 64 字节，未显式列出的尾部由对齐填充。FIFO 单槽 1024 字节、32 槽，大核只在前 64 字节放记录，其余清零。

合法性：magic 和 version 必须匹配；`standing <= total`；`fallen == total - standing`。类别映射是 label 0 → `fallen`，label 1 → `standing`；其他 label 不计入。

## 4. TCP 状态协议

生产格式：

```text
STATUS seq=<uint> total=<uint> standing=<uint> fallen=<uint> state=<SAFE|FALL>\n
```

例子：

```text
STATUS seq=81 total=4 standing=3 fallen=1 state=FALL
STATUS seq=82 total=2 standing=2 fallen=0 state=SAFE
```

语义约束：

- `total == standing + fallen`；
- `SAFE` 必须 `fallen == 0`；
- `FALL` 必须 `fallen > 0`；
- 网络不允许发送 `UNKNOWN`，UNKNOWN 只由接收端超时产生；
- 每条记录必须以 `\n` 结束，接收端也兼容 `\r\n`。

TCP 是有序字节流，没有记录边界。一次 `recv()` 可能得到半条、恰好一条或多条。`LineBuffer` 先追加字节，再循环取换行前的完整行，剩余字节继续保留。固定缓冲区满而仍无换行时，必须拒绝/清空，而不是越界。

当前 K230 生产客户端只单向发送，不等待 ACK；纯 C 学习协议保留格式化/解析基础。若未来增加 ACK，要定义超时和重发语义，避免状态客户端因等待 ACK 阻塞 FIFO 消费。

## 5. RTSP 接口

默认：

```text
port:    8554
session: BackChannelTest
URL:     rtsp://<K230-Linux-IP>:8554/BackChannelTest
codec:   H.264 Main Profile
```

`rtspServer -t h264` 的 codec 声明必须与大核 VENC 输出一致。时间戳直接使用 VENC PTS，不由小核重新生成。

## 6. 早期 UDP JSON 兼容接口

Qt 的 `DetectionCountReceiver` 接收：

```json
{"fall": 1, "no_fall": 2}
```

两个字段必须是非负整数且不超过 `INT_MAX`；两秒没有合法包后发出无效/过期状态。该模块不是 TCP STATUS 的替代实现，部署时必须明确使用哪条状态链路。

## 7. 线程与所有权接口

- `RtspDecoder` 及所有 FFmpeg 对象属于 decoder QThread。
- `PlayerController` 属于 GUI 线程，通过 queued signal 启动解码。
- `frameReady` 发送深拷贝 QImage，GUI 不接触 AVFrame。
- `stopRequested_` 是原子变量，供 FFmpeg interrupt callback 跨线程读取。
- DataFIFO 共享指针在 READ_DONE 之后立即失效；需要长期使用的数据必须先复制。
