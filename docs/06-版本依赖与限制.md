# 版本、依赖与已知限制

## 交付基线

交付包以工作区中的 `falldown_rtsp_status_safe` 源码为 K230 主线，以 `falldown_rtsp_status_safe_v3.elf`、修复 DataFIFO 释放顺序的 `rtspServer` 和 `k230_status_tcp_client_v2` 为配套运行文件。历史 v1～v8/诊断版本没有重复塞入 ZIP，详见 `legacy/README.md`。

## 外部依赖

| 组件 | 用途 | 是否包含 |
|---|---|---|
| K230 SDK | VICAP/VB/VENC/MAPI/DataFIFO、板型配置、链接脚本 | 否 |
| nncase runtime/ai2d | KModel 加载、预处理、NPU 推理 | 仅源码引用；运行库来自 SDK |
| K230 OpenCV 静态库 | OSD、图像工具 | 否，来自 SDK |
| Live555/KdRtspServer | RTSP/RTP 会话 | 否，来自 K230 SDK |
| Xuantie RISC-V Linux GCC | 构建小核 Linux 程序 | 否 |
| Qt 5.12+ | RK3566 GUI、线程、网络、测试 | 否 |
| FFmpeg libav* | RTSP 解复用、H.264 解码、像素转换 | 否 |
| GCC/Make | 纯 C 状态服务和测试 | 否 |

K230 SDK 是强版本依赖。尤其媒体静态库需要与板端固件匹配；历史记录显示兼容路径使用 `Nov 6 2024` VICP 资产，较旧 `Jun 14 2024` 资产曾被判定不兼容。这个日期只能作为当前硬件的历史线索，不应替代你对实际固件/SDK 的正式版本核对。

## 模型限制

本包包含可部署 KModel，不包含：训练数据、标注、训练配置、训练脚本、PyTorch 权重、ONNX、量化校准集或原始 nncase 转换命令。因此可以复现应用集成和部署，不能完整复现模型训练。若需要真正“模型从零”，必须补齐这些资产，并记录许可证、数据隐私、类别定义和评估指标。

现有代码把类别固定为 `Fall`、`NoFall`，anchors 固定为 YOLOv5 常见三组，输出固定为三尺度。替换成 anchor-free YOLO、不同类别顺序或不同输出节点时，必须重写后处理，不能只替换 `.kmodel`。

## 当前源码与预编译文件的关系

代码注释不改变可执行语句；交付目录重命名为 `big-core/little-core` 后，CMake 的目录引用被相应调整，并要求显式传入 SDK 根目录。预编译二进制是在原构建树生成，不会因为注释改变。若你修改源码或换 SDK，应重新构建全部相关二进制并重新做板端验收。

## Qt 状态显示限制

Qt 工程当前直接显示 RTSP 视频，并保留旧 UDP JSON 计数接收器。TCP STATUS 服务端是独立纯 C 程序，尚未把 SAFE/FALL/UNKNOWN 状态嵌入 Qt 主窗口。交付文档明确保持这个事实；若产品要求单窗口状态显示，需要后续新增 Qt TCP 客户端或让独立 daemon 通过 Unix Domain Socket 向 Qt 提供快照。

## 网络与安全限制

- RTSP 没有认证和加密，适合受控局域网，不应直接暴露到公网。
- TCP 状态协议没有 TLS、身份认证或防重放。
- 状态服务当前一次只维护一个 K230 连接，新连接会替换旧连接。
- IP 与端口通过命令行/源码默认值配置，没有统一配置文件。
- 没有 systemd 服务文件、开机自启、日志轮转和健康检查。

用于生产时，应至少增加网络隔离、防火墙、服务管理、配置文件、日志限流和进程监控。

## 性能与实时性限制

大核摄像头路径仍包含帧复制，OSD 合并也使用 OpenCV；这些设计优先保证清晰和可调试，而不是绝对零拷贝。状态约每 30 帧发布一次，因此不是逐帧遥测。TCP 连接失败会让小核客户端休眠后重试，但不会阻塞大核。

## 本次可验证与不可验证内容

当前 Windows/WSL 主机已经验证：文件完整性、注释覆盖、文档覆盖、ZIP 解压与哈希、纯 C 测试，以及 K230 大核、RTSP 小核和状态客户端的交叉编译。Qt5 已存在，但由于缺少 FFmpeg 开发包，本次未运行 Qt 测试。

必须在真实板卡验证：传感器初始化、NPU 推理、硬件 H.264、跨核 DataFIFO、K230 小核 RTSP、K230↔RK3566 真实网络、Qt 图形显示。交叉编译成功只证明源码与选定 SDK 能生成目标 ELF，不能替代板端运行。

## 预编译二进制中的历史路径

为保留已知板端基线，`k230/bin` 中的预编译文件按原样交付。二进制字符串/调试信息中仍能看到历史 Windows 工作区、Linux home 和 SDK 路径；预编译状态客户端的动态段还保留历史 SDK 库目录 RPATH。它当前只依赖标准运行库，RPATH 不等于打包了该目录，但这属于可移植性和隐私元数据限制。

本交付保证源码、脚本、清单和说明文档没有私人绝对路径；不声称原样基线二进制没有。若发布到公开环境，应使用 `-ffile-prefix-map`、关闭 RPATH 后重新构建，并完成真实板端回归，再替换基线文件。
