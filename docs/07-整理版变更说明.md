# 整理版变更说明

交付包以“不改原工作区”为原则，所有修改都发生在复制后的目录。预编译 ELF、KModel、`rtspServer` 和状态客户端没有被二进制修改。

## 仅说明性修改

- 55 个 C/C++/头文件、CMake、Makefile 和 Shell 文件增加中文文件头。
- K230 推理、两个 DataFIFO、RTSP 发送、状态复制、TCP 行缓冲、FFmpeg 中断和 QImage 深拷贝位置增加关键行内注释。
- 增加从零教程、架构、逐文件、部署、协议、排障和限制文档。

## 构建目录调整

原 K230 源目录中的 `big` 在交付包中重命名为 `big-core`，顶层 `add_subdirectory()` 同步修改。小核 RTSP CMake 不再依赖原工作区的多层相对路径，而是要求显式传入 `K230_SDK_ROOT`。`build.sh` 使用脚本自身绝对目录构造 out-of-source build，避免从不同当前目录调用时找错 toolchain file。

这些调整影响“怎样找到 SDK 和源码目录”，不改变推理、编码、DataFIFO 或 RTSP 运行逻辑。

## 协议解析修复

WSL 首次运行 `make test` 时，合法 FALL 行解析失败。根因是 `sscanf` 格式包含 4 个无符号整数、1 个 state 字符串和 1 个专门捕获尾随字符的 `%c`：合法行只返回 5 项，原代码却要求 6 项。结果是合法行被拒绝，而带空格尾随内容的非法行反而可能被接受。

整理版先新增 `test_reject_trailing_characters()` 并确认旧代码失败，再把条件从 `fields != 6` 修正为 `fields != 5`。随后完整执行 `make clean && make && make test`，编译启用了 `-Wall -Wextra -Werror -pedantic`，测试通过。

该源码修复发生在 RK3566 纯 C 状态服务中，不影响交付的 K230 预编译二进制。使用修复后的服务端时应在 RK3566 上从源码重新执行 `make`。

## RTSP 线程返回值修复

小核 RTSP 首次交叉编译时，编译器报告 `read_send()` 返回类型为 `void*`，但函数结束处没有返回值。整理版使用 `-Werror=return-type` 重新构建并确认旧代码失败，然后在正常退出路径显式 `return nullptr`。该返回值会被 `std::thread` 忽略，但补全它可以消除未定义返回值并使严格编译通过。

## 最终审查修复

- 状态服务改用单调时钟记录最后一条合法 STATUS；持续非法行或半包不再让旧 SAFE/FALL 无限续期。
- 数字字段先按纯十进制字符串校验，再用 `strtoul` 检查范围，拒绝负号、正号和超出 `unsigned int` 的值。
- Qt 手动重连会先停止旧 decoder，等线程结束后创建新线程；立即 Stop 不再被 queued start 清除，析构等待线程真正结束。
- `RetryPolicy` 明确标为尚未接入的实验代码，不再声称播放器已有自动退避重连。
- 独立模型脚本使用实际交付名 `falldown_detect_standalone.elf`。
- 验证报告明确披露原样预编译二进制内仍含历史绝对路径/RPATH。

## 没有完成或伪造的修改

- 没有将 TCP 状态服务强行合并进 Qt 主窗口；当前边界在文档中如实说明。
- 没有补造不存在的 YOLO 训练、ONNX 或量化转换资产。
- 没有在缺少 K230 SDK/板卡时声称大核和小核已重新编译或联调通过。
- 没有把历史实验 ELF 混入默认运行目录。
