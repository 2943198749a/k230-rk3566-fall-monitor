# 故障排查与验收

## 排查原则

先找最早失败的边界，不要同时修改模型、摄像头、编码、RTSP 和网络。推荐顺序：文件哈希 → 进程/地址 → 大核模型与媒体日志 → DataFIFO → 小核网络服务 → RK3566 客户端。

## 常见故障

### 大核启动即报模型加载失败

检查 KModel 是否完整、路径是否正确、nncase 版本是否与构建 ELF 匹配。比较 SHA-256。若是重新转换的模型，核对输入/输出布局和量化设置。

### 摄像头或 VICP 初始化失败

检查板型宏、sensor 驱动、排线、固件与 SDK 媒体库版本。已知风险是使用与板端固件不一致的 VICP 静态库；编译成功不能证明运行时兼容。

### 有推理日志但没有检测框

先用独立测试图验证模型。再检查目标阈值、NMS 阈值、类别顺序、输入颜色/CHW 排列、letterbox 和 stride 8/16/32 输出顺序。不要直接把阈值降到极低，这会掩盖预处理错误。

### RTSP 连接失败

确认顺序是大核先创建视频 FIFO，小核再使用本次打印的 `PhyAddr`。检查端口：

```sh
netstat -lntp | grep 8554
```

确认 URL session 是 `/BackChannelTest`，codec 参数是 `-t h264`，两板路由/防火墙正常。

### 能连接但黑屏或花屏

最先检查大核和 `rtspServer` 是否来自匹配 SDK/同一 DataFIFO 布局。确认读取方是在 `SendVideoData()` 后才 `READ_DONE`。用 `ffprobe` 查看是否识别 H.264、分辨率和 SPS/PPS；若 header 丢失，新客户端可能无法解码。

### 状态客户端提示不能打开 FIFO

状态 FIFO 地址必须来自 `STATUS_FIFO_PHY_ADDR`，不是视频 `PhyAddr`。地址通常在大核每次重启后重新获取；确认大核状态功能已启用且仍在运行。

### RK3566 一直 UNKNOWN

依次检查：RK3566 服务是否监听 9000；K230 能否 ping RK3566；状态客户端目标 IP/端口；状态客户端是否收到 DataFIFO 数据；服务端是否因非法字段丢弃。可以先用纯 C 模拟客户端证明服务端正常。

### TCP 偶尔出现两条连在一起或半条

这是正常 TCP 行为，不是网络损坏。必须经过 `LineBuffer` 按换行分帧，不能把一次 `recv()` 当作一条消息。

### Qt 点击停止仍不退出

检查 `AVFormatContext::interrupt_callback` 是否已设置，停止标志是否为 atomic，线程退出后是否清理 decoder。不要从 GUI 线程直接释放 FFmpeg 上下文。

### Qt 有解码但画面随机损坏

确认跨线程发出的 QImage 是深拷贝。若移除 `image.copy()`，解码循环或栈对象结束后 GUI 可能访问失效像素。

### Qt 默认地址连不上

当前 `app_config.h` 的默认地址是 `192.168.50.2`，而历史板端 runbook 使用过 `192.168.10.2`。在界面输入实际地址，或根据现场网段修改默认值后重新编译。

## 分阶段验收表

### A. 文件和构建

- [ ] KModel、ELF、rtspServer、状态客户端 SHA-256 与交付清单一致。
- [ ] 纯 C `make test` 全部通过。
- [ ] Qt `ctest --output-on-failure` 全部通过。
- [ ] 大核 ELF 的 `file` 输出为目标 RISC-V/RT-Smart 格式。
- [ ] 小核程序的 `file` 输出为 RISC-V Linux，不是 x86-64。

### B. 模型

- [ ] 测试图能得到合理 Fall/NoFall 框。
- [ ] 摄像头输入颜色、方向和画面尺寸正常。
- [ ] 目标阈值 0.5、NMS 0.45 下不出现明显重复框。
- [ ] 多人场景满足 total = standing + fallen。

### C. 视频

- [ ] 大核打印 `payload type is H264` 和视频 FIFO 地址。
- [ ] 小核 RTSP 端口 8554 正在监听。
- [ ] ffprobe 识别 H.264 和实际分辨率。
- [ ] ffplay/Qt 连续播放至少两分钟，无持续解码错误、花屏或空白。
- [ ] 关闭并重新连接播放器，视频恢复且无需重启大核。

### D. 状态

- [ ] 大核打印独立 `STATUS_FIFO_PHY_ADDR`。
- [ ] K230 客户端输出已连接 RK3566。
- [ ] 无跌倒时收到合法 SAFE。
- [ ] 有跌倒时收到合法 FALL。
- [ ] 场景恢复后重新变为 SAFE。
- [ ] 停止 K230 状态客户端，RK3566 三秒后显示 UNKNOWN。
- [ ] 重启客户端，状态自动恢复。

### E. 故障隔离

- [ ] 停止 RK3566 状态服务，RTSP 继续正常至少一分钟。
- [ ] 重启状态服务，K230 客户端重连且大核无需重启。
- [ ] 停止 RTSP 服务，状态仍持续到达 RK3566。
- [ ] 状态 FIFO 满或 RK3566 断网时，大核推理和编码无明显阻塞。
- [ ] Qt Stop、Reconnect、关闭窗口均无残留线程或进程。
