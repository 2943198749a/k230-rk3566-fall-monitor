# 编译、部署与运行

## 1. 构建前提

K230 源码必须放到 Linux/WSL 构建环境，且 `K230_SDK_ROOT` 必须指向与目标板固件媒体运行时匹配的完整 SDK。历史联调中，板端兼容媒体库包含 `Nov 6 2024` 标记；使用较旧 `Jun 14 2024` VICP 库曾产生不兼容结果。不要仅因为“编译通过”就认为 ABI 一定匹配。

建议目录：

```text
/home/user/work/k230_sdk/                         # 官方/厂商 SDK
/home/user/work/k230-rk3566-yolo-falldown/       # 本交付包
```

先设置：

```bash
export K230_SDK_ROOT=/home/user/work/k230_sdk
export DELIVERY_ROOT=/home/user/work/k230-rk3566-yolo-falldown
export PATH="$K230_SDK_ROOT/toolchain/riscv64-linux-musleabi_for_x86_64-pc-linux-gnu/bin:$PATH"
```

上面的 PATH 是大核 RT-Smart/musl 工具链。小核 Linux 使用另一套 Xuantie glibc 工具链，不能混用。

## 2. 构建 K230 大核 ELF

大核 CMake 会读取 SDK 的 nncase、OpenCV、MPP 和链接脚本。工具链文件的准确位置取决于 SDK 分支；优先使用 SDK 中 `src/reference/ai_poc/cmake/Riscv64.cmake` 或当前 AI POC 构建系统使用的同一份文件。

```bash
cmake -S "$DELIVERY_ROOT/k230" -B /tmp/k230-falldown-big \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE="$K230_SDK_ROOT/src/reference/ai_poc/cmake/Riscv64.cmake" \
  -DK230_SDK_ROOT="$K230_SDK_ROOT"

cmake --build /tmp/k230-falldown-big \
  --target falldown_rtsp_big.elf --parallel 2
```

检查输出：

```bash
file /tmp/k230-falldown-big/big-core/falldown_rtsp_big.elf
sha256sum /tmp/k230-falldown-big/big-core/falldown_rtsp_big.elf
strings /tmp/k230-falldown-big/big-core/falldown_rtsp_big.elf | grep -F 'payload type is H264'
```

若 SDK 的 umbrella CMake 会注入额外板型宏，应将 `k230/big-core` 放回 SDK 的 `src/reference/ai_poc` 体系构建，不能随意删掉板型定义。交付包的预编译 `k230/bin/falldown_rtsp_status_safe_v3.elf` 可用于已验证环境，但新板卡仍需核对固件和传感器。

## 3. 构建 K230 小核 RTSP 服务

```bash
cd "$DELIVERY_ROOT/k230/little-core/rtsp-server"
export K230_SDK_ROOT
export TOOLCHAIN_BIN=/opt/toolchain/Xuantie-900-gcc-linux-5.10.4-glibc-x86_64-V2.6.0/bin
./build.sh
```

手动等价命令：

```bash
cmake -S . -B out \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE="$PWD/cmake/Riscv64.cmake" \
  -DK230_SDK_ROOT="$K230_SDK_ROOT"
cmake --build out --parallel
```

这个目标链接 DataFIFO slave、MAPI、RTSP server 和 Live555 静态库。若链接时报 undefined reference，先检查 SDK 是否完整、库是 host/slave 哪一侧、以及交叉编译器 ABI；不要通过删除库来掩盖错误。

## 4. 构建 K230 小核状态客户端

```bash
TOOL="$K230_SDK_ROOT/toolchain/Xuantie-900-gcc-linux-5.10.4-glibc-x86_64-V2.6.0/bin"

cmake -S "$DELIVERY_ROOT/k230/little-core/status-client" \
  -B /tmp/k230-status-client \
  -DCMAKE_SYSTEM_NAME=Linux \
  -DCMAKE_CXX_COMPILER="$TOOL/riscv64-unknown-linux-gnu-g++" \
  -DK230_SDK_ASSET_ROOT="$K230_SDK_ROOT"

cmake --build /tmp/k230-status-client \
  --target k230_status_tcp_client --parallel 2
```

`file` 输出应显示 RISC-V Linux 可执行文件，而不是 x86-64。

## 5. 构建 RK3566 状态服务

在 RK3566、WSL 或普通 Linux：

```bash
cd "$DELIVERY_ROOT/rk3566/status-service"
make clean
make
make test
```

`make test` 应覆盖合法/非法消息、格式化、TCP 半包和粘包。模拟联调：

```bash
# terminal A
./rk3566_status_tcp_server 9000

# terminal B
./k230_status_tcp_client 127.0.0.1 9000
```

## 6. 构建 RK3566 Qt 播放器

Debian/Ubuntu 类系统安装依赖：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential cmake pkg-config \
  qtbase5-dev qtbase5-dev-tools \
  libavformat-dev libavcodec-dev libavutil-dev libswscale-dev
```

配置、编译、测试：

```bash
cd "$DELIVERY_ROOT/rk3566/qt-viewer"
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

如果 RK3566 使用 Qt 5.12 的 sysroot 交叉编译，需要额外提供 RK3566 toolchain file 和目标 sysroot；本包没有绑定某一款 RK3566 发行版，因此默认展示板上原生编译。

## 7. 复制到 K230

在 K230 小核可见的共享目录中新建一个不会覆盖旧部署的目录：

```sh
mkdir -p /sharefs/app/falldown_delivery
```

复制：

```text
k230/bin/falldown_rtsp_status_safe_v3.elf -> /sharefs/app/falldown_delivery/
k230/bin/rtspServer                       -> /sharefs/app/falldown_delivery/
k230/bin/k230_status_tcp_client           -> /sharefs/app/falldown_delivery/
k230/model/yolov5n-falldown.kmodel        -> /sharefs/app/falldown_delivery/
```

然后：

```sh
chmod +x /sharefs/app/falldown_delivery/falldown_rtsp_status_safe_v3.elf
chmod +x /sharefs/app/falldown_delivery/rtspServer
chmod +x /sharefs/app/falldown_delivery/k230_status_tcp_client
sha256sum /sharefs/app/falldown_delivery/*
```

将结果与 `manifests/SHA256SUMS.txt` 对比。KModel 和 ELF 被截断时，程序可能表现为加载失败或不可预测错误，不能跳过哈希。

## 8. 正确启动顺序

### 8.1 RK3566 状态服务

```bash
./rk3566_status_tcp_server 9000
```

确保 RK3566 的有线地址是 K230 能访问的地址，例如 `192.168.10.3`。

### 8.2 K230 大核 COM7

```sh
cd /sharefs/app/falldown_delivery
./falldown_rtsp_status_safe_v3.elf yolov5n-falldown.kmodel 0.5 0.45 0
```

必须看到 H.264、视频 FIFO `PhyAddr` 和独立的 `STATUS_FIFO_PHY_ADDR`。地址由本次启动产生，不要盲目照抄历史值。

### 8.3 K230 小核 COM6 的 RTSP

假设本次视频日志打印 `PhyAddr: 1628c000`：

```sh
cd /sharefs/app/falldown_delivery
./rtspServer -p 1628c000 -t h264
```

必须用 `h264`，因为交付大核源码在所有板型分支都设置 `K_PT_H264` 和 `VENC_PROFILE_H264_MAIN`。

### 8.4 K230 小核 COM6 的状态客户端

假设状态地址打印为 `STATUS_FIFO_PHY_ADDR=0x17f00000`：

```sh
./k230_status_tcp_client 17f00000 192.168.10.3 9000
```

不要把视频 FIFO 地址传给状态客户端，也不要把状态 FIFO 地址传给 RTSP 服务。两种记录布局完全不同。

### 8.5 RK3566 播放

```bash
ffprobe -rtsp_transport tcp rtsp://192.168.10.2:8554/BackChannelTest
ffplay  -rtsp_transport tcp rtsp://192.168.10.2:8554/BackChannelTest
```

Qt 默认地址在 `rk3566/qt-viewer/src/app_config.h`。交付源码目前是 `192.168.50.2`，与上述示例网段不同；可在界面输入实际 URL，或重新编译前修改默认值。

## 9. 停止顺序

先停止 RK3566 播放器和 K230 小核两个网络进程，再在大核终端输入 `q`。大核负责停止推理线程、VENC、DataFIFO 和 VB。测试新版本时始终使用新文件名和新目录，保留已知可用版本作为回滚。
